Section 02 · the conductor

Living-Dossier pipeline

Seven steps from identifier intake to saved report. Parallel collection in step three, convergent enrichment in step four, branching synthesis at step six. Click a step to inspect.

01
Input
Create dossier directory at data/dossiers/<target_id>/. Validate identifiers.
02
Expand
Generate name variations. Phone correlation. Build search groups.
03
Collect
Parallel data agents fan out. Write sections 01–07. Summarize each.
04
Enrich
Discover phones / emails. Search new IDs. Loop until convergence.
05
Compile
Cross-references. Contact network. Voter check. Cross-target links.
06
Assess
Branches by workflow. Targeting → 7 LLM scans. Trace skips. LEO summary-only.
07
Final
Executive summary. Narrative report. Save versioned dossier.

        Section 03 · execution modes

        Five workflow types

        The same pipeline, five ways. Targeting runs everything. LEO scopes to selected agents. Trace skips assessments. Single-agent is one card, one section. Chat is conversational with optional plan execution.

        ◎
        Targeting
        // full sweep
        1. All 7 data agents
        2. Enrichment loop
        3. Compile step
        4. All 7 assessments
        5. Exec summary + narrative
        6. Saved report v1..vN
        heaviest · all stages
        ◐
        LEO
        // user-selected
        1. Selected agents only
        2. Enrichment loop scoped
        3. Compile step
        4. Skip assessments
        5. Exec summary + narrative
        6. Saved report
        scoped · gated by agent_keys
        ◑
        Trace
        // no assessments
        1. All 7 data agents
        2. Enrichment loop
        3. Compile step
        4. Trace narrative
        5. Saved report
        where target appears

        Single
        // direct search card
        1. One agent only
        2. Lightweight store
        3. Write section + summary
        4. Return raw to UI
        5. No cross-agent calls
        fastest · isolated

        2. Regex extract IDs
        3. Plan executor or LLM
        4. Tool calls audited

        Section 05 · what survives a restart

        Persistence layers

        Three SQLite databases plus a filesystem dossier tree per target. Records are content-hashed for dedup, reports are versioned v1..vN, and the knowledge graph stores entities, triples, and bidirectional links.

        Section 07 · regression archaeology

        The LEO single-agent leak

        Bug #2. User selects one agent for a LEO run; pipeline writes sections from all seven. Root cause: enrichment tracker, contact_search, and the agent_query tool all bypassed scope. Fix gates them on the active agent set.

        Before · BUG #2
        Input
        User: "LEO with SIGINT only"
        ↓
        step 3 collect
        sigint runs ✓
        ↓
        step 4 enrich
        tracker.get_search_queue() returns phones in [sigint, fisa, geoint, cne, travel, osint, intel]
        ↓
        step 4b contact
        contact_tool.execute() with no scope — scans all 14 agent DBs
        ↓
        query_agent
        no gating — LLM can call any agent
        ↓
        result
        ✘ travel / cne / fisa / etc. sections also written
        Symptom Cross-pollution between agents. LEO with one selected agent produced a full dossier.
        After · scope-gated
        Input
        User: "LEO with SIGINT only"
        ↓
        step 3 collect
        sigint runs ✓
        ↓
        step 4 enrich
        tracker.get_search_queue(allowed_agents=["sigint"]) returns phones in [sigint] only
        ↓
        step 4b contact
        contact_tool.execute(search_agents=allowed) — only sigint DB scanned
        ↓
        query_agent
        checks _active_agent_keys — rejects out-of-scope
        ↓
        result
        ✓ Only sigint DB touched
        Files touched tools/shared/enrichment_tracker.py · get_search_queue(allowed_agents) + has_converged(allowed_agents)
        tools/shared/dossier_pipeline.py · run() sets active scope · _step_4_enrich passes allowed · _run_secondary_search(search_agents)
        tools/shared/contact_search.py · execute(search_agents) honored
        agents/orchestrator.py · set_active_agent_scope() · _handle_agent_query() rejects OOS
