  MULTILINGUAL KEYWORD SEARCH (KS) — STEP-BY-STEP MANUAL PORT
  Target: ai-agent-platform / V2 / backend
  Goal:   Make the indicator_scanner pre-filter and LLM hint multilingual
          (Arabic primary), so chunks written in Arabic actually reach the
          LLM for the right indicators instead of being silently discarded
          by the English-only substring gate.
  Generated: 2026-05-29

--------------------------------------------------------------------------------
WHAT WAS WRONG (root cause)
--------------------------------------------------------------------------------
indicator_scanner._prefilter_chunk does a plain  term.lower() in chunk_lower
substring check against each indicator's English-only trigger_terms array.
All 7 assessment templates (moti) ship with English-only triggers.

Consequence on Arabic-language source data:
  * A chunk that says "اعطاه ظرف فيه فلوس كاش" (handed over an envelope of
    cash) contains zero English bribe/cash tokens. The pre-filter drops it
    BEFORE the LLM ever sees it. M4 (cash payments / bribes) silently misses
    the finding.
  * A chunk that says "تم تشخيصه بسرطان" never hits "cancer". F1 (medical
    condition) misses it.
  * Same for "فصل من الوزارة" (fired from the ministry) -> K3, "الجهاد
    والشهيد" -> I3, etc.

There was also no Unicode normalization anywhere in the codebase, so even
the same Arabic word would fail to match across documents because of
tashkeel (diacritics): "فُلُوس" != "فلوس" by exact code-point match.

--------------------------------------------------------------------------------
WHAT THE FIX DOES
--------------------------------------------------------------------------------
1. NEW shared module  tools/shared/text_normalize.py
     - normalize_for_match(): NFKC, lowercase, strip Arabic diacritics +
       tatweel, fold alef variants (أ إ آ ٱ) -> ا, fold alef-maksura ى -> ي.
       Conservative — does NOT fold teh-marbuta (ة) -> heh (ه), which can
       change meaning. Latin-only text passes through unchanged.

2. NEW dictionary  tools/shared/keyword_synonyms.json
     - Maps canonical English atoms ("money", "debt", "salary", "cancer",
       "hospital", "fired", "jihad", "ministry", ...) to Arabic forms
       across MSA + Iraqi + Egyptian + Levantine.
     - Arabic-only. Latin transliterations (flous, masari, jihad, ...) are
       intentionally NOT included.

3. EDIT  tools/shared/indicator_scanner.py
     - Load the synonyms file at __init__ (graceful fallback if missing).
     - New helpers _expand_terms() / _lookup_synonyms() take an indicator's
       English trigger_terms and return originals + Arabic synonyms

       word inside multi-word triggers.
     - _prefilter_chunk normalizes BOTH the chunk and each expanded term

       diacritics / alef forms compare equal.
     - _build_scan_prompt appends 2 Arabic forms to the per-indicator

"""Conservative Arabic text normalization for substring keyword matching.

WHY THIS EXISTS
  The indicator_scanner pre-filter is a plain `term.lower() in chunk_lower`
  substring check. Python handles Unicode fine, BUT exact code-point match
  means a diacritic on a single letter breaks the match: a chunk containing
  "فُلُوس" (money, with vowel marks) will NOT match a trigger "فلوس". Real
  intelligence dossiers contain both forms — typed input is usually bare,
  but copy-paste from OCR / Quran / news / formal documents carries tashkeel.

  Likewise Arabic has multiple acceptable forms of alef (ا أ إ آ) and the
  ya / alef-maksura pair (ي ى). A trigger written one way will miss a
  document written the other way.

WHAT IT NORMALIZES (conservative, no semantic loss)
  - Strips Arabic diacritics (tashkeel: fatha, kasra, damma, shadda, sukun,
    tanween) and the decorative tatweel (kashida).
  - Folds alef variants (أ إ آ ٱ) -> ا.
  - Folds alef-maksura (ى) -> ya (ي).
  - Lowercases (no-op on Arabic but matters for any Latin in the text).
  - NFKC normalize so visually-identical code points compare equal.

WHAT IT DELIBERATELY DOES NOT NORMALIZE
  - teh-marbuta (ة) is NOT folded to heh (ه). The folding is common in
    search engines but can change meaning ("حياة" life vs "حياه" greet
    him), so we keep them distinct. Trigger lists can include both forms
    if needed.
  - Hamza on waw / ya (ؤ ئ) is left alone for the same reason.

USED BY
  - tools/shared/indicator_scanner.py  (pre-filter + LLM hint expansion)

See export/08_MULTILINGUAL_KEYWORDS.txt for the manual port instructions.
"""

import re
import unicodedata

# Arabic combining marks (tashkeel) + tatweel/kashida.
#   U+064B–U+065F   diacritics (fathatan, dammatan, kasratan, fatha, damma,
#                   kasra, shadda, sukun, plus assorted Quranic marks)
#   U+0670          dagger alef (small superscript alef)
#   U+0640          tatweel (decorative line, no semantic content)
_ARABIC_MARKS_RE = re.compile(r"[ً-ٰٟـ]")

# Folding table: alef variants + alef-maksura -> ya.
_ARABIC_FOLD = str.maketrans({
    "أ": "ا", "إ": "ا", "آ": "ا", "ٱ": "ا",  # alef with hamza/madda/wasla
    "ى": "ي",                                  # alef-maksura -> ya
})


def strip_arabic_marks(text: str) -> str:
    """Remove Arabic diacritics (tashkeel) and tatweel from `text`.
    Pure-Latin text is returned unchanged."""
    if not text:
        return text
    return _ARABIC_MARKS_RE.sub("", text)


def normalize_for_match(text: str) -> str:
    """Canonicalize `text` for substring keyword matching.

    Pipeline:
      1. NFKC normalize (compose canonical forms, fold compatibility variants).
      2. Lowercase (no-op on Arabic; needed for any Latin / mixed text).
      3. Strip Arabic diacritics + tatweel.
      4. Fold alef variants -> bare alef; alef-maksura -> ya.

    Apply this to BOTH the chunk and each trigger term before the
    `term in chunk` substring test, so equivalent forms compare equal.
    """
    if not text:
        return ""
    text = unicodedata.normalize("NFKC", text)
    text = text.lower()
    text = strip_arabic_marks(text)
    text = text.translate(_ARABIC_FOLD)
    return text

    def _expand_terms(self, terms: List[str]) -> List[str]:
        # Return `terms` plus any Arabic synonyms registered in the
        # keyword_synonyms.json file (lookup by the exact term and by each
        # whitespace-separated word inside multi-word terms). Order is preserved
        # and duplicates (post-normalization) are removed. Returns originals
        # unchanged when no synonyms file is loaded.
        if not self._synonyms:
            return list(terms)
        expanded: List[str] = []
        seen_norm: set = set()
        for term in terms:
            for cand in self._lookup_synonyms(term):
                norm = normalize_for_match(cand)
                if norm and norm not in seen_norm:
                    seen_norm.add(norm)
                    expanded.append(cand)
        return expanded

    def _lookup_synonyms(self, term: str) -> List[str]:
        # Yield `term` followed by its Arabic synonyms — both for the full
        # phrase and for each word it contains. A pre-filter substring hit on
        # any single Arabic atom is enough to keep the chunk.
        out: List[str] = [term]
        key = term.lower().strip()
        if key in self._synonyms:
            out.extend(self._synonyms[key])
        # Also look up each word — so "salary low" pulls in synonyms for
        # both "salary" and "low" if either is registered.
        if " " in key:
            for word in key.split():
                if word in self._synonyms and word != key:
                    out.extend(self._synonyms[word])
        return out

    def _prefilter_chunk(self, chunk_lower: str,
                          indicators: List[Dict]) -> List[Dict]:
        # Keep only indicators whose (expanded) trigger_terms have at least
        # one keyword hit in the chunk. Saves LLM calls on irrelevant chunks.
        #
        # Pre-filter expansion: each English trigger term is expanded through
        # the Arabic synonyms dictionary so a chunk written in Arabic still
        # passes the gate. Both chunk and terms are run through
        # normalize_for_match() so diacritics / alef variants compare equal.
        #
        # If an indicator has no trigger_terms at all (rare), keep it (LLM
        # must evaluate by semantics).
        chunk_norm = normalize_for_match(chunk_lower)
        out: List[Dict] = []
        for ind in indicators:
            terms = (ind.get("trigger_terms", []) +
                      ind.get("trigger_terms_primary", []) +
                      ind.get("trigger_terms_secondary", []))
            if not terms:
                out.append(ind)
                continue
            expanded = self._expand_terms(terms)
            for term in expanded:
                if normalize_for_match(term) in chunk_norm:
                    out.append(ind)
                    break
        return out

def _ind(scanner, assessment_id: str, ind_id: str):
    """Pull a single indicator by id from the named assessment template."""
    tpl = scanner.load(assessment_id)
    for cat in tpl["categories"]:
        for ind in cat["indicators"]:
            if ind["id"] == ind_id:
                return ind
    raise KeyError(f"{assessment_id}::{ind_id} not found")


def _passes(scanner, chunk: str, ind: dict) -> bool:
    """True if this indicator survives the pre-filter for this chunk."""
    return scanner._prefilter_chunk(chunk.lower(), [ind]) != []

def test_diacritic_stripping():
    print("\n=== test_diacritic_stripping ===")
    pairs = [
        ("فُلُوس", "فلوس"),                # tashkeel + bare
        ("شَهِيدٌ", "شهيد"),                # full tashkeel + tanween
        ("رَشْوَةٌ", "رشوة"),                # vowel marks + sukun + tanween
    ]
    ok = True
    for a, b in pairs:
        ok &= _check(f"{a!r} == {b!r}", normalize_for_match(a) == normalize_for_match(b))
    return ok
