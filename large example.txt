  Goal:   Never lose facts on million-char dossiers. Hardens the two-tier
          synthesizer + section summarizer + assessment scanner so that
          (a) no chunk can ever overflow the LLM context window,
          (b) context-length failures are split-and-retried, and

--------------------------------------------------------------------------------
WHAT WAS WRONG (root cause)
--------------------------------------------------------------------------------
All three map-reduce chunkers split text ONLY on "\n\n" and emitted whatever
sat between two separators — with NO size cap. So:
  * a single 500,000-char record, or
  * a 2,000,000-char blob containing no "\n\n" at all,
became ONE oversize chunk. The LLM rejected it with a context-length error,
and each caller then silently discarded that chunk:

  LOCATION                              ON OVERSIZE/FAILED CHUNK      RESULT
  indicator_scanner (assessment scan)   returned empty results        LOST facts  <-- the bug you hit
  living_dossier._chunked_summary MAP   chunk -> "[Chunk N failed]"    LOST data
  living_dossier._compress_summary      text[:target_chars]            LOST ~90%
  plan_executor Tier-2 pattern agent    patterns dropped               degraded analysis

There was also NO failure visibility: a skipped chunk looked identical to a
fully-scanned one, which violates the platform's "completeness & accuracy"
guarantee.

--------------------------------------------------------------------------------
WHAT THE FIX DOES
--------------------------------------------------------------------------------
1. NEW shared module  tools/shared/chunking.py
     - chunk_text(): guarantees EVERY chunk <= max_size. A record larger than
       the cap is hard-split at sentence -> newline -> whitespace -> hard-cut.
     - call_with_split_retry(): on a context-length error, bisect the piece
       and retry each half down to a floor; report unrecoverable pieces via
       an on_drop callback so coverage gaps are tracked.
     - is_context_length_error(): distinguishes "too big" from rate-limit/5xx.
2. All three _chunk_text() methods now DELEGATE to the shared chunker.
3. Sub-agent MAP scan, Tier-2 pattern agent, and the assessment scanner use
   split-and-retry; on a truly-unrecoverable piece the RAW text is kept so its
   facts still reach the final synthesis.
4. Summarizer NEVER truncates: keeps raw chunk text on failure, and
   _compress_summary recurses (depth-guarded) instead of slicing.
5. IndicatorScanner stats gain: chunks_total, chunks_failed, chars_unscanned,
   coverage_complete — and the assessment markdown shows a "COVERAGE GAP"
   banner whenever anything could not be scanned.

"""Bulletproof text chunking for large-data map-reduce.

WHY THIS EXISTS
  The platform's map-reduce paths (data-agent two-tier synthesis, dossier
  section summarization, checklist assessment scanning) all split a large
  blob into chunks and send each chunk to the LLM. The original chunkers
  split ONLY on "\n\n" record boundaries and emitted whatever sat between
  two separators — no matter how large. A single 500K-char record (or a
  2M-char blob with no "\n\n" at all) became ONE oversize chunk, which the
  LLM rejected with a context-length error. The caller then silently
  dropped that chunk → lost facts the platform promised to capture.

WHAT THIS GUARANTEES
  chunk_text() never emits a chunk larger than `max_size`. When a single
  record/paragraph exceeds the cap, it is hard-split at the best available
  boundary (sentence -> newline -> whitespace -> hard cut). No chunk can
  overflow the LLM context window.

  call_with_split_retry() is the runtime safety net: if an LLM call still
  fails with a context-length error (token != char; system prompt +
  indicator list add overhead), it recursively splits the offending piece
  in half and retries each half down to a floor size, so every byte is
  eventually scanned. Genuinely unrecoverable pieces are reported via an
  on_drop callback so the caller can track coverage gaps instead of
  silently losing data.

USED BY
  - tools/shared/plan_executor.py        (_chunk_text delegates here)
  - tools/shared/living_dossier.py       (_chunk_text delegates here)
  - tools/shared/indicator_scanner.py    (_chunk_text + per-chunk retry)

See export/07_LARGE_DATA_FIXES.txt (LD = Large-Data fixes) for the manual
port instructions.
"""

import re
from typing import Callable, List, Optional

DEFAULT_MAX_SIZE = 3000

# Substrings that indicate the model rejected the prompt for being too
# large (vs. a transient rate-limit / 5xx which the llm_provider already
# retries). Matched case-insensitively against str(exception).
#
# Calibrated against real provider error strings (the platform's
# llm_provider.chat() raises LLMError wrapping the underlying message):
#   OpenAI:    "This model's maximum context length is 8192 tokens..."
#              "Please reduce the length of the messages"
#   Anthropic: "prompt is too long: 209527 tokens > 200000 maximum"
#              "input length and max_tokens exceed context limit"
#   Gemini:    "input token count (X) exceeds the maximum number of tokens"
#   413 / OpenAI-compatible (vLLM, Ollama, LM Studio): "request entity too
#              large", "context length", "maximum context length"
_CONTEXT_LIMIT_PATTERNS = re.compile(
    r"context.?length|context window|context limit|maximum context|"
    r"exceed.{0,30}context|input length|"
    r"too many tokens|reduce the length|prompt is too long|"
    r"input is too long|string too long|exceeds? the maximum|"
    r"max(?:imum)?[ _]tokens|too large|413|request entity too large",
    re.IGNORECASE,
)


def is_context_length_error(exc) -> bool:
    """True if the exception looks like a context/length rejection (so
    splitting the input could help). False for rate-limit/network/etc.,
    where splitting would not help.

    A provider error that carries an explicit ``is_rate_limit=True`` flag
    (the platform's LLMError does) is never treated as a context error —
    splitting a rate-limited request would not help."""
    if getattr(exc, "is_rate_limit", False):
        return False
    return bool(_CONTEXT_LIMIT_PATTERNS.search(str(exc)))


def _best_cut(window: str) -> int:
    """Pick the best index to cut `window` at, searching the trailing ~20%
    for a natural boundary. Priority: sentence terminator -> newline ->
    whitespace -> hard cut at the end of the window.
    Always returns a value in (0, len(window)]."""
    n = len(window)
    if n == 0:
        return 0
    floor = max(1, n - n // 5)  # only look in the last 20% of the window
    for pat in (". ", ".\n", "! ", "? ", "?\n", "!\n", "\n"):
        idx = window.rfind(pat, floor)
        if idx > 0:
            return idx + len(pat)
    idx = window.rfind(" ", floor)
    if idx > 0:
        return idx + 1
    return n  # no boundary found — hard cut


def split_oversize(segment: str, max_size: int) -> List[str]:
    """Hard-split a single segment that exceeds `max_size` into pieces each
    <= max_size, cutting at the best available boundary each time."""
    if max_size <= 0:
        return [segment]
    out: List[str] = []
    remaining = segment
    # Guard against pathological inputs causing an infinite loop.
    while len(remaining) > max_size:
        window = remaining[:max_size]
        cut = _best_cut(window)
        if cut <= 0:  # safety — never make zero progress
            cut = max_size
        out.append(remaining[:cut].strip())
        remaining = remaining[cut:]
    if remaining.strip():
        out.append(remaining.strip())
    return [c for c in out if c]


def chunk_text(text: str,
               max_size: int = DEFAULT_MAX_SIZE,
               separator: str = "\n\n") -> List[str]:
    """Split `text` into chunks each guaranteed <= `max_size` chars.

    Splits on `separator` (record/paragraph boundary) first, packing
    consecutive segments up to the cap. Any single segment larger than the
    cap is hard-split via split_oversize() so the guarantee always holds.

    Returns [] for empty input, [text] when text already fits.
    """
    if not text:
        return []
    if len(text) <= max_size:
        return [text]

    sep_len = len(separator)
    segments = [s for s in text.split(separator) if s.strip()]
    if not segments:
        return split_oversize(text, max_size)

    chunks: List[str] = []
    current = ""
    for seg in segments:
        # Oversize single segment: flush current, then hard-split this one.
        if len(seg) > max_size:
            if current:
                chunks.append(current)
                current = ""
            chunks.extend(split_oversize(seg, max_size))
            continue
        # Packing: would adding this segment overflow the current chunk?
        if current and len(current) + sep_len + len(seg) > max_size:
            chunks.append(current)
            current = seg
        else:
            current = (current + separator + seg) if current else seg
    if current:
        chunks.append(current)
    return chunks


def _split_point(text: str) -> int:
    """Find a roughly-midpoint boundary to bisect `text` for split-retry.
    Prefers a separator/newline/space near the middle; falls back to the
    exact midpoint."""
    mid = len(text) // 2
    # search outward from the midpoint for a clean boundary
    for pat in ("\n\n", "\n", ". ", " "):
        # look in a window around the midpoint
        lo = text.rfind(pat, 0, mid)
        hi = text.find(pat, mid)
        # choose whichever boundary is closest to mid
        cand = []
        if lo > 0:
            cand.append(lo + len(pat))
        if hi > 0:
            cand.append(hi + len(pat))
        if cand:
            return min(cand, key=lambda x: abs(x - mid))
    return mid


def call_with_split_retry(
    call_fn: Callable[[str], object],
    text: str,
    *,
    floor: int = 500,
    on_drop: Optional[Callable[[str, Exception], None]] = None,
) -> List[object]:
    """Run ``call_fn(text)``; on a context-length error, bisect and retry.

    call_fn(text) -> result        (must raise on failure)
    floor: pieces this small or smaller are not split further; if they
           still fail they are reported to on_drop and skipped.
    on_drop(piece, exc): optional callback invoked for each piece that
           could not be processed even after splitting (lets the caller
           record a coverage gap instead of silently losing the data).

    Returns a flat list of results from every sub-piece that succeeded
    (one entry per successful call; order preserved left-to-right).
    """
    try:
        return [call_fn(text)]
    except Exception as e:
        # Non-context errors (rate-limit exhaustion, network, auth, etc.)
        # won't be helped by splitting — is_context_length_error() returns
        # False for them (incl. anything flagged is_rate_limit). Pieces
        # at/under the floor can't be split further. Report and skip.
        if len(text) <= floor or not is_context_length_error(e):
            if on_drop:
                on_drop(text, e)
            return []
        mid = _split_point(text)
        if mid <= 0 or mid >= len(text):
            mid = len(text) // 2
        left, right = text[:mid], text[mid:]
        results: List[object] = []
        results.extend(call_with_split_retry(
            call_fn, left, floor=floor, on_drop=on_drop))
        results.extend(call_with_split_retry(
            call_fn, right, floor=floor, on_drop=on_drop))
        return results

class _CtxFailLLM:
    """Fails on prompts whose user message exceeds `limit` chars (simulating
    a context-length rejection); otherwise returns a benign empty result."""
    def __init__(self, limit):
        self.limit = limit

    def chat(self, messages, temperature=0.0, max_tokens=4000, **kw):
        user = next((m["content"] for m in messages if m["role"] == "user"), "")
        if len(user) > self.limit:
            raise RuntimeError("This model's maximum context length is 8192 tokens")
        return {"content": json.dumps({"results": [], "novel": []})}

        Emergency fallback when recursive summarization doesn't converge.

            recurse on the merged result (bounded by _depth) until it fits;
            at the depth guard return the merged text WHOLE, never sliced.
          - single call fails -> return the text WHOLE (complete but
            uncompressed) rather than slicing it.
        Either way no facts are lost.
        """

        MAX_INPUT = 80000   # safe input size for a single LLM call
        MAX_DEPTH = 5       # convergence guard (each round compresses ~10x)

        # If text is too large for a single call, compress slice-by-slice.
        if len(text) > MAX_INPUT:
            print(f"    [SUMMARY] {agent_key.upper()}: text too large "
                  f"({len(text)} chars), compressing in "
                  f"{len(text) // MAX_INPUT + 1} slices (depth={_depth})...")
            chunk_summaries = []
            for i in range(0, len(text), MAX_INPUT):
                chunk_summaries.append(
                    self._compress_summary(agent_key, text[i:i + MAX_INPUT],
                                           _depth=_depth + 1))
            merged = "\n\n".join(chunk_summaries)

            # already fits or we've hit the depth guard (return merged WHOLE
            # — never truncated).
            if len(merged) > MAX_INPUT and _depth < MAX_DEPTH:
                return self._compress_summary(agent_key, merged,
                                              _depth=_depth + 1)
            return merged

                     "Cite max 10 record IDs. Be ruthlessly concise."},

                max_tokens=2000,
            )
